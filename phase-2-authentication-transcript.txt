Career Commander — Phase 2 Transcript
======================================

User request
------------
Implement authentication and user identity for a multi-user Career Commander system.
Ensure user-owned data is isolated server-side and test signup, duplicate accounts,
login, invalid login, logout, protected routes, cross-user access, password reset,
and invalid/expired authentication.

Repository state before Phase 2
-------------------------------
The repository contained only an empty CareerCommandermainidea.md file. No framework,
frontend, backend, database, authentication, routes, or tests existed.

Implementation decisions
------------------------
- Used Node.js built-in HTTP server and SQLite support; no new frontend framework.
- Used server-rendered HTML with a small Career Commander-styled stylesheet.
- Used salted scrypt password hashing.
- Used opaque random session tokens stored only as SHA-256 hashes.
- Used HttpOnly, SameSite=Lax session cookies.
- Rotated sessions on signup, login, and password changes.
- Used one-time, expiring password reset tokens stored only as hashes.
- Added CSRF token validation and same-origin checks for state-changing requests.
- Added security headers, CSP, XSS-safe HTML escaping, body-size limits, and basic
  login rate limiting.
- Resolved ownership exclusively from the authenticated session principal.
- Added SQLite ownership-filtered profile access to demonstrate the IDOR boundary.
- Added audit events for account creation, login, logout, password changes, and reset.
- Did not add Google OAuth because no credentials or infrastructure existed.
- Did not continue into onboarding or domain workflows.
