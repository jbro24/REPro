Career Commander — Phase 13 Gap-to-Evidence Roadmap & Application Workflow
Date: 2026-10-06

Baseline
--------
Before implementation:
- npm test: 47 total; 46 passed; 0 failed; 1 skipped.
- Existing deterministic Matcher, Scorer, Gap Analyzer, report, Evidence Locker,
  authentication, and security controls were present.
- Roadmap persistence existed, but generation was generic, status mutation and
  roadmap evidence linkage were missing, and Applications was a placeholder.

Implementation
--------------
1. Gap-to-evidence roadmap
- Expanded src/roadmap.js with concrete, deterministic work templates.
- AWS produces deployment/documentation work.
- Docker produces containerization/documentation work.
- PostgreSQL produces a database-backed feature/schema/query task.
- TypeScript and Python produce focused artifact-and-test tasks.
- Other requirements receive a bounded reviewable artifact task.
- Required gaps sort before preferred gaps.
- Empty persisted gaps produce no roadmap items.
- Statuses are PLANNED, IN_PROGRESS, COMPLETED, and SKIPPED.

2. Roadmap persistence and evidence linkage
- Existing roadmap_items was reused.
- Regeneration preserves matching item IDs, statuses, and linked evidence.
- Roadmap items can be status-updated with ownership checks.
- Existing Evidence Locker records can be linked to roadmap items.
- Evidence remains user-provided context and does not automatically verify a skill.
- Opportunity deletion cascades roadmap and roadmap-evidence relationships safely.

3. Application workflow
- Added a user-owned application draft model tied one-to-one to an opportunity.
- Draft statuses: DRAFT, IN_REVIEW, READY_FOR_REVIEW, ARCHIVED.
- Drafts are generated only after requirements, matches, score, and gaps exist.
- Draft content uses candidate profile, skills, projects, evidence context, and
  persisted gaps. It does not invent employment, achievements, certifications, or
  years of experience.
- Drafts are editable and re-checked when saved.

4. Claim grounding
- Added application_claims records with SUPPORTED, UNSUPPORTED, or NEEDS_REVIEW.
- Candidate overclaims against a persisted gap, such as professional AWS
  experience when AWS is not verified, are marked UNSUPPORTED.
- Claims without a clear supporting profile/evidence basis remain NEEDS_REVIEW.
- Claims show supporting Evidence Locker records where available.

5. Human review
- Applications page now lists real drafts.
- Opportunity reports offer Prepare application draft.
- Application review shows editable draft text, claim verdicts, reasons, linked
  evidence, review notes, and review state.
- There is no application-submission route or automatic submission status.

Security and ownership
----------------------
- Roadmap mutations require an authenticated session and CSRF validation.
- Application mutations require an authenticated session and CSRF validation.
- Roadmap, application, opportunity, and evidence lookups are user-owned.
- A second user received 404 for another user’s application and roadmap mutation.
- Deleting the opportunity made the related application and roadmap unavailable.
- Existing authentication, secure sessions, same-origin, XSS escaping, CSP, input
  limits, URL validation, and audit events were preserved.

Database changes
----------------
Additive tables created in src/db.js:
- roadmap_evidence_links
  - unique (user_id, roadmap_item_id, evidence_id)
  - indexes on (user_id, roadmap_item_id) and (user_id, evidence_id)
- applications
  - unique (user_id, opportunity_id)
  - status constraint: DRAFT, IN_REVIEW, READY_FOR_REVIEW, ARCHIVED
  - index on (user_id, updated_at)
- application_claims
  - verdict constraint: SUPPORTED, UNSUPPORTED, NEEDS_REVIEW
  - unique (application_id, claim_order)
  - index on (user_id, application_id, claim_order)

Existing roadmap rows with legacy SUGGESTED status are normalized to PLANNED.
No destructive migration and no data reset were performed.
