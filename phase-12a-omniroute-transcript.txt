Live OmniRoute Integration and End-to-End Verification
Date: 2026-10-06

Scope
-----
Phase 12A only. No Phase 13+ functionality was implemented.

Inspection
---------
The repository already had provider injection points in createApp for search,
analyst, mailbox, company signals, project relevance, report synthesis, and a
general OmniRoute object. It did not contain a concrete live OmniRoute HTTP
implementation. The server previously created the application without a live
provider.

The existing deterministic JobRequirements validation, Matcher, Scorer, Gap
Analyzer, automatic analysis runner, normalization, deduplication,
provenance, report, authentication, CSRF, ownership, and security behavior
were preserved.

Implementation
--------------
Added src/omniRoute.js with:

- OmniRouteClient and typed provider errors.
- Provider-agnostic HTTP search boundary using POST /search.
- Structured chat boundary using /chat/completions for analyst and enrichment
  stages.
- Configurable timeout, bounded retry behavior, optional API key, and optional
  model selection.
- Response validation for search and structured LLM output.
- Safe operational logging of provider, endpoint type, stage, duration,
  success/failure, and retry count. Secrets and raw private content are not
  logged.

Updated src/server.js to inject the configured OmniRoute implementation through
the existing search and analyst provider boundaries. The domain and pipeline
remain provider-agnostic.

Deterministic boundary verification
------------------------------------
The live adapter only interprets/enriches. It does not calculate candidate
fit, MATCH/PARTIAL/MISSING, scores, or gaps. Existing tests passed confirming:

- Matcher respects evidence states and does not calculate a score.
- Scorer is deterministic and handles weights, partials, missing values, and
  edge cases.
- Gap Analyzer only emits evidence-grounded PARTIAL and MISSING gaps.
- Analyst output is validated before deterministic stages.
- Untrusted job content remains data and cannot override analyst instructions.

Duplicate, retry, and preservation behavior
---------------------------------------------
Existing workflow integration tests passed for normalization, deduplication,
additional provenance, automatic analysis, and preservation of existing
opportunities when a provider fails. The new adapter also reports retry and
typed failure state. A live duplicate scan was not possible without the
provider.
